# 引用写进消息，前缀缓存只替你付一次

provider 按**字节前缀**缓存。一个请求的最前面永远是系统提示（instructions + index），
后面才是 transcript。所以**同一段文本放在越前面，它后面的东西越可能还是热的**。

## 两种拿到文件内容的方式

| 方式 | 文本落在哪 | 付费方式 |
| --- | --- | --- |
| `bash: cat plan.md` | 一条 tool_result，在 transcript 中间 | 它在 transcript 里，每一轮都跟着前缀一起重发，而且它在**上一条 index 之后**——改一次 index 就把它后面全冲掉 |
| 消息里写 `@file: plan.md` | index，紧跟 instructions | 一次进系统提示，之后每轮都是缓存命中；文件改了只追加一行新 prompt |

所以：**你希望这一整轮工作里反复看到的东西，写进消息；只读一次的东西，用 bash。**

## index 是什么，什么时候重建

`index` = 本次会话里所有消息命名的引用的正文 + 会话目录里 `AGENTS.md` 的正文（递归：
引用里再写引用也会进来），按 `prefix_cache` 算出的最省顺序拼成一段，接在 instructions 后面。

它**每一步都重建**：文件改了 → 正文变了 → 追加一行 prompt 行（旧行不动，SPEC 的
"已发送的不改"），provider 那边从改动处开始重算。没改则字节相同，一行都不写。

## 哪条消息能进 index

| 消息 | `@file:` | `@skill:` |
| --- | --- | --- |
| 会话的**第一条** user 消息（新会话、刚被 `heir` 清空、刚 spawn 的 subagent 的 brief） | 进 index，消息里保持字面 | 进 index，消息里保持字面 |
| 之后的普通消息 | 进 index（下一次重建时，会写一行新 prompt） | **被就地替换成一行 metadata，永远不进 index** |

表格第二行是唯一容易踩的坑：`@skill:` 只认"第一句话"。所以**技能要在开场就点名**，
不要等到第三轮才说"顺便看看 @skill:foo"。

同一条规则也解释了两件常见的事：

- 一条消息（比如 `Context notice`）里写的 `@skill:prefix-cache` 是**真的会被索引**的——
  它是 user 消息，正文会进 index。
- 一个已经进了 index 的 skill，它的正文里再写 `@skill:bar`，`bar` 的正文也跟着进——
  所以这份文件可以被别的 skill 引用一次，正文只存一遍。

## 拼写规则

引用必须长成 `@kind:` 加上**紧跟着的一个词**。解析器先按空白切词，再剥掉前后的 ASCII
引号、括号、反引号，最后从右边剥掉 `, ; : . ! ? ) ] } " ' \``。

| 写法 | 结果 |
| --- | --- |
| `@file: plan.md` | 认 |
| `@file:plan.md` | 认（补全插的就是这种） |
| `(see @file:plan.md).`、`` `@file:plan.md` ``、`"@file:plan.md"` | 认 |
| `@file: plan.md, and also this` | 认，只取 `plan.md` |
| `@file: dir with space/x.md` | **不认**：值是一个词，只取到 `dir` |
| `@file: plan.md，然后继续` | **不认**：中文标点既不是分隔符也不会被剥掉，值变成 `plan.md，然后继续` |
| `@File: plan.md` | **不认**：前缀大小写敏感 |
| `[link](@file:plan.md)` | **不认**：开头的 `[` 之后不是 `@` |

中文句子最容易踩后两种：**引用后面一定要有空白**（空格或换行），别直接接 `，` `。` `）`。

## 写错的后果是静默

读不出来的引用**不报错**：消息照发，单词照样留着，index 里没有它，日志里没有一行。
所以你写错时唯一的信号是"模型还是自己去读了那个文件"。

不确定时：引用后面紧跟一句人话确认，或先 `ls` 一下那个词，都不花什么钱。

## 两个"第一句话"的时刻

这两处是整轮工作里最值钱的消息，值得把它们要读的东西都写清楚：

- **spawn 一个子 agent**：`send_message` 的 `--message` 就是它的第一条 user 消息。
  把 brief 要它读的文件、要用的技能都写成引用（见 `@skill:subagent`）。
- **`heir` 的第一课**：`--note` 由脚本用 `send_message` 发给刚清空的会话，所以它也是
  第一条 user 消息。第一课里写 `@file: <路径>`，继承人下一次请求就带着正文，不必再读一遍。
