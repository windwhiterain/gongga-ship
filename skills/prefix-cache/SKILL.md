# 引用写进消息，前缀缓存只替你付一次

provider 按**字节前缀**缓存。一个请求的最前面永远是系统提示（instructions + index），
后面才是 transcript。所以**同一段文本放在越前面，它后面的东西越可能还是热的**。

## 两种拿到文件内容的方式

| 方式 | 文本落在哪 | 付费方式 |
| --- | --- | --- |
| `exec: cat plan.md` | 一条 tool_result，在 transcript 中间 | 它在 transcript 里，每一轮都跟着前缀一起重发，而且它在**上一条 index 之后**——改一次 index 就把它后面全冲掉 |
| 消息里写 `@file(plan.md)` | index（只在会话的第一条消息里），紧跟 instructions | 一次进系统提示，之后每轮都是缓存命中；之后改文件不再重发 |

所以：**你希望这一整轮工作里反复看到的东西，写进消息；只读一次的东西，用 exec。**

## index 是什么，什么时候写定

`index` = 会话第一条 user 消息命名的引用的正文 + 会话目录里 `AGENTS.md` 的正文（递归：
引用里再写引用也会进来），按 `prefix_cache` 算出的最省顺序拼成一段，接在 instructions 后面。

它**只写一次**：第一个请求写下那行 prompt，之后 `prompt_in_force` 有行就再也不渲染
（`agent::index_of` 只在那一次跑）。后来改了文件、后来消息里又点了新的引用，都不会补进
index，也不会追加新 prompt 行——index 里永远是第一句话那一刻的根。

## 哪条消息能进 index

| 消息 | `@file(...)` | `@skill(...)` |
| --- | --- | --- |
| 会话的**第一条** user 消息（新会话、刚被 `handoff` 清空、刚 spawn 的 subagent 的 brief） | 进 index；消息里保持字面 | 进 index；消息里换成指针 `@skill(<名字>) (<它 SKILL.md 的路径>)` |
| 之后的普通消息 | 不进 index（已经写定）；消息里就是一个路径字面 | 不进 index；消息里换成同一个指针，正文得模型自己去读 |

表格第二行是唯一容易踩的坑：`@skill(...)` 只认"第一句话"。所以**技能要在开场就点名**，
不要等到第三轮才说"顺便看看 @skill(foo)"。

同一条规则也解释了两件常见的事：

- `handoff` 的交接笔记、spawn 的 brief 都是第一条消息，所以它们点名的技能正文才进 index；
  `Context notice` 是轮中注入的 user 消息，index 已经写定，它点名的技能只剩指针。
- 一个已经进了 index 的 skill，它的正文里再写 `@skill(bar)`，`bar` 的正文也跟着进——
  所以这份文件可以被别的 skill 引用一次，正文只存一遍。

## 拼写规则

引用是一条 `@kind(值)`：`@file(...)`、`@skill(...)`、`@image(...)`。**括号是分隔符**，
值从 `(` 后面开始，到配对的 `)` 结束——所以它前后都不用留空白，值里可以有空格，也可以有括号
（解析器数括号的深度，还会跳过引号里的）。

| 写法 | 结果 |
| --- | --- |
| `@file(plan.md)` | 认，补全插的就是这种 |
| `看下@file(plan.md)这个文件` | 认：`@` 不必在词首，值也不必停在空格上 |
| `@file(docs/my plan.md)` | 认：值里有空格，中间不用加引号 |
| `@file(notes/a (1) b.md)` | 认：括号成对计数 |
| `@skill(self-control)` | 认 |
| `@file` / `@file(plan.md` | **不认**：没有配对的 `(` 与 `)`，就只是一段文字 |
| `@File(plan.md)` | **不认**：前缀大小写敏感 |

写法只有一条要记：**右括号别漏**。

## 写错的后果是静默

读不出来的引用**不报错**：消息照发，单词照样留着，index 里没有它，日志里没有一行。
所以你写错时唯一的信号是"模型还是自己去读了那个文件"。

不确定时：引用后面紧跟一句人话确认，或先 `ls` 一下那个词，都不花什么钱。

## 两个"第一句话"的时刻

这两处是整轮工作里最值钱的消息，值得把它们要读的东西都写清楚：

- **spawn 一个子 agent**：`send_message --session <子会话> <brief>` 的 brief 就是它的第一条 user 消息。
  把 brief 要它读的文件、要用的技能都写成引用（见 `@skill(subagent)`）。
- **`handoff` 的交接笔记**：`--note` 由脚本用 `send_message` 发给刚清空的会话，所以它也是
  第一条 user 消息。笔记里写 `@file(<路径>)`，接手方下一次请求就带着正文，不必再读一遍。
